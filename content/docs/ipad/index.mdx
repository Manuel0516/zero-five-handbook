## Source and persistence

The secret-free client template is
`zero-five-infra/wireguard/ipad-alpha.conf.example`. It is separate from the
legacy eight-node full-mesh examples; those examples contain existing phone
and MacBook relay-address drift and must not overwrite live files wholesale.

The narrowly scoped helper
`zero-five-infra/scripts/persist_ipad_wireguard.py` runs on Alpha or Delta.
It adds only the iPad peer (Alpha) or iPad return route (Delta), preserving
existing peer configuration. It refuses conflicting addresses, creates a
root-only rollback copy, writes a root-owned mode-0600 replacement, and checks
the resulting file. It does not restart WireGuard or save unrelated runtime drift.

From the owner's SSH session on Alpha:

```bash
sudo python3 /home/manuel/services/zero-five-infra/scripts/persist_ipad_wireguard.py --apply
ssh -t manuel@10.40.0.2 'sudo python3 /home/manuel/services/zero-five-infra/scripts/persist_ipad_wireguard.py --apply'
```

The helper has been staged on both hosts; enter sudo passwords only in the
trusted terminal, not in chat. After applying, rerun both commands without
`--apply`: each must report that the persistent configuration is already present.
The agent must read back the same verification results before calling this
persistent enrollment complete. Do not bounce `wg0` over a mesh SSH connection.

## Verification

1. Activate the tunnel on the iPad.
2. In Safari, open `https://docs.zero-five.space` and a normal internet site.
3. Test an existing private AdGuard-only service appropriate for the iPad to
   verify internal DNS; public DNS resolution of the handbook alone is not
   proof that all private names resolve.
4. On Alpha, check the exact public key with `sudo wg show wg0 latest-handshakes`
   and `sudo wg show wg0 transfer`. Expect a recent nonzero handshake and
   increasing transfer counts. A configured peer with handshake `0` is not
   a working client.
5. Check Delta's route with `ip route get 10.40.0.24` and verify the Alpha peer
   includes `10.40.0.24/32` using `sudo wg show wg0 allowed-ips`.
6. Confirm both persistent checks above. Verify persistence across the next
   planned maintenance restart, not by interrupting an active admin connection.

Alpha-to-handbook HTTPS returned HTTP 200 during setup, but that is a server-side
smoke check, not an iPad end-to-end result.

## Revocation and rollback

On Alpha, remove only the iPad runtime peer:

```bash
sudo wg set wg0 peer dbAF/F2xkHF9ViLv3s59DOnNxywXq0k/DcAO9M6TiVA= remove
```

Remove its peer block from Alpha's persistent configuration with `sudoedit`.
On Delta remove only `.24/32` from the Alpha peer's AllowedIPs, leaving all other
routes intact, in both runtime and persistent state; then remove the explicit
`.24/32` kernel route if present. Do not restore a whole rollback file if newer
unrelated peer changes have since been made. Disable/delete the tunnel on the iPad.
