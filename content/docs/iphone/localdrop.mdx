[LocalDrop](https://github.com/Manuel0516/localdrop) syncs the clipboard and
transfers files between the desktop machines. Its v1 is **push-only from the
iPhone**: the phone cannot run a LocalDrop daemon (no `config.toml` on iOS),
so the iPhone uses **Shortcuts** to POST clipboard/text and files to a desktop
daemon. **Linux → iPhone is not supported in v1** (the reverse direction).

If you are setting up the MSI ⇄ MacBook pair, see the MacBook
[LocalDrop](/docs/macbook/localdrop) and MSI
[LocalDrop](/docs/laptop-msi/localdrop) pages instead. This page only covers
sending **from the phone**.

## What the phone can do (v1)

| Direction | Supported? |
| --- | --- |
| iPhone → Linux (MSI) — clipboard & files | ✅ via Shortcuts |
| iPhone → MacBook — clipboard & files | ✅ via Shortcuts |
| Linux/Mac → iPhone | ❌ not supported in v1 |

## Destination: the Linux/MSI desktop's static IP

The phone posts to the **MSI Linux desktop** at its **static private IP**:

```
http://192.168.1.110:8765/clipboard   (clipboard text)
http://192.168.1.110:8765/file        (file bytes)
```

`192.168.1.110` is reserved static (it doesn't change), and the MSI daemon
listens on `0.0.0.0:8765` so it answers on its LAN address. When the target is
the MacBook instead, use `http://192.168.1.109:8765` (MacBook's static IP).

> The phone is a one-way HTTP **client** — it never opens a listener, so the
> desktop cannot push audio to it. Only the Shortcuts requests above matter.

## Setup (iPhone)

1. Confirm the MSI desktop daemon is running and listening on `0.0.0.0:8765`
   (MSI's `config.toml`), reachable at `192.168.1.110`.
2. Record the `shared_token` from the MSI/MacBook `config.toml`
   (`[security] shared_token`) — it must match on the phone and the desktop.
3. In the **Shortcuts** app:
   - **Send clipboard to Linux:** `Get Clipboard` → `Get Contents of URL`
     (URL `http://192.168.1.110:8765/clipboard`, method **POST**, headers
     `X-LocalDrop-Token: <token>` + `Content-Type: application/json`, body:
     `source = "iphone"`, `text = <Clipboard variable>`).
   - **Send file to Linux:** `Get File` → `Get Contents of URL`
     (URL `http://192.168.1.110:8765/file`, method **POST**, headers
     `X-LocalDrop-Token: <token>` + `X-LocalDrop-Filename: <name>` +
     `Content-Type: application/octet-stream`, body = file).
4. Trigger the shortcut from the Share Sheet when sending a file.

## Security

- Keep port `8765` **LAN-only** — the desktop daemon must listen on the LAN,
  never be forwarded from the router. Do **not** add a router port-forward for
  `8765`: LocalDrop is plaintext, and with DDNS now keeping the home WAN
  reachable, a forward would expose the clipboard + transferred files to the
  internet.
- The home router currently reports **zero** UPnP port-mappings (verified
  2026-08-23), so nothing is exposed via UPnP today.
- The `shared_token` is a secret: it must be identical on the desktop and the
  phone shortcut, but it is never stored in the handbook or the infra repo.

## Troubleshooting

- `401` — the `X-LocalDrop-Token` header the shortcut sends doesn't match the
  desktop's `shared_token`.
- Timeout/refused — confirm the MSI daemon is up and listening on the LAN IP;
  confirm the phone and MSI are on the same LAN (the phone must be on **WiFi**
  — sending over cellular won't reach `192.168.1.110`).
- Clipboard sync between the desktops themselves (MSI ⇄ MacBook) is the
  separate pair configured on those machines — see
  [MacBook LocalDrop](/docs/macbook/localdrop).
