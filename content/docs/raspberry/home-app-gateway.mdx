Delta runs a private reverse proxy (**Traefik v2.11**) that routes home app
names to LAN/mesh backends. Names are private AdGuard rewrites → Delta's mesh
IP; Traefik terminates TLS and forwards by `Host` header to the machine that
actually runs the app (Beta, Gamma, …). Clients only ever need Delta
(`10.8.0.2`) in their WireGuard `AllowedIPs` — **no new peers per app**.

Deployed 2026-08-22, following the AdGuard Home deploy on Delta.

## The model

```
name.zero-five.space ──► AdGuard rewrite → 10.8.0.2 (Delta)
                              │
                              ▼
                     Traefik :443 on Delta (terminates TLS, *.zero-five.space cert)
                              │  Host: name.zero-five.space
                              ▼
                     LAN backend (e.g. https://192.168.1.166:8006 Proxmox)
```

Why this design (user decisions, 2026-08-22):

- **Names stay private — NOT in Cloudflare.** The user explicitly does not
  want every home app name enumerated in public DNS. AdGuard rewrites keep
  them Zone-2 only. (An alternative — grey-cloud Cloudflare A records like
  the Alpha VPN-only pattern — was offered and rejected for home names.)
- **No new peers on clients.** Every client already reaches `10.8.0.2`
  (Delta). Traefik does the LAN hop, so adding an app never touches client
  WireGuard configs.
- **Traefik v2.11** — matches the Alpha hub conventions (do NOT bump to v3;
  the Docker provider API mismatch and the file-provider patterns are proven).
  Caddy was considered (lighter, auto internal CA) but consistency won.

## Internal CA — the deliberate independence choice

Delta's certs are signed by its **own internal CA** — never a public CA
(Let's Encrypt / Cloudflare). This is a **user-mandated design decision
(2026-08-22)**: private services must not depend on Cloudflare or any public
infrastructure. A Let's Encrypt wildcard via Cloudflare DNS-01 was considered
and **rejected** — it would re-introduce the external dependency the private
DNS exists to remove. The price is a one-time CA trust per device (~1 min);
after that everything works offline, forever, with no renewal.

**CA files (Delta, root-owned):**
- Private key: `/home/manuel/services/proxy/ca/ca.key` (mode 600, never leaves Delta)
- Public cert: `/home/manuel/services/proxy/ca/ca.pem` (copies: `/home/manuel/zero-five-ca.pem` on Delta, `proxy/zero-five-ca.pem` in the infra repo)
- Wildcard leaf: `/home/manuel/services/proxy/certs/zero-five.pem` (signed by CA)
- **Fullchain** (what Traefik serves): `/home/manuel/services/proxy/certs/zero-five-fullchain.pem`

**Backup is critical:** the CA key is the single point of failure — losing it
forces every device to re-trust a new CA. `/home/manuel/services/proxy` is in
`delta-paths` (added 2026-08-22); verify the 21:00 backup actually covers it.
Full rebuild runbook: [Delta Rebuild & Recovery](/docs/raspberry/delta-rebuild).

### How to trust a device (one-time)

- **macOS (MacBook)**: `sudo security add-trusted-cert -d -r trustRoot -k
  /Library/Keychains/System.keychain zero-five-ca.pem` (or double-click →
  Keychain Access → Always Trust)
- **iOS (iPhone)**: send `zero-five-ca.pem` to the phone (AirDrop/Mail) →
  install profile → Settings → General → About → Certificate Trust Settings
  → enable full trust for "Zero Five Internal CA"
- **Linux**: copy to `/usr/local/share/ca-certificates/zero-five-ca.crt` →
  `sudo update-ca-certificates`

Fetch the cert: `scp manuel@10.8.0.2:/home/manuel/zero-five-ca.pem .` (or from
the infra repo `proxy/zero-five-ca.pem`).

**PITFALL — serve the full chain.** Traefik's dynamic TLS must point at a
**fullchain** file (leaf + CA concatenated), not just the leaf. With only the
leaf, browsers report `SEC_ERROR_UNKNOWN_ISSUER` even after the CA is
installed ("the site isn't sending intermediate certificates we trust").
Build it once: `cat certs/zero-five.pem ca/ca.pem >
certs/zero-five-fullchain.pem` and reference `/certs/zero-five-fullchain.pem`
in the routes' `tls.certificates`. Verified 2026-08-22: fullchain serves 2
certs, subjects leaf + CA.

## Adding an app (the pattern)

1. **AdGuard rewrite** (Settings → DNS rewrites, or yaml): `app.zero-five.space
   → 10.8.0.2`
2. **Traefik route** in `dynamic/<app>.yml` — for an HTTPS LAN backend with a
   self-signed cert (Proxmox, Jellyfin, …) use the `lan-selfsigned`
   transport:

```yaml
http:
  serversTransports:
    lan-selfsigned:          # define once, reuse per app
      insecureSkipVerify: true

  routers:
    <app>:
      rule: "Host(`app.zero-five.space`)"
      entryPoints: [websecure]
      service: <app>
      tls: {}

  services:
    <app>:
      loadBalancer:
        serversTransport: lan-selfsigned
        servers:
          - url: "https://192.168.1.XXX:PORT"
```

3. `sudo docker compose -f /home/manuel/services/proxy/compose.yaml restart`
   (dynamic files hot-reload, but a restart guarantees pickup) — actually
   only needed if the static config changed; `dynamic/` files are watched.

## Firewall note

No nftables change was needed: the forward-chain accepts added for AdGuard
(`iifname "br-*"`, `iifname "docker0"`) already cover Traefik's container →
LAN traffic. Container → LAN egress is Docker-masqueraded out eth0, return
traffic matches `ct state established,related`.

## Automatic DNS adoption (router DHCP — the "no per-device config" path)

The user wants AdGuard DNS **without touching each device**. The clean way on
the LAN is the **router's DHCP server**: point it at Delta's LAN address as
the DNS server, and every device that joins the network (phone, laptop, TV,
NAS…) receives AdGuard automatically — no per-device settings.

On the home router (192.168.1.1 admin UI), set:

- **DHCP / DNS server → `192.168.1.106`** (Delta's LAN IP; static/reserved)

Then all LAN clients resolve private names (`proxmox.zero-five.space`, …) and
get ad-blocking out of the box.

**Resilience — always pair with a fallback.** A single DNS server is a SPOF:
if Delta is down, clients lose resolution (looks like losing internet).
Configure a **secondary DNS** on every path:

- WG configs: `DNS = 10.8.0.2, 1.1.1.1` (try AdGuard, fall back to Cloudflare)
- Router DHCP: primary `192.168.1.106`, secondary `192.168.1.1` (or `1.1.1.1`)

Applied 2026-08-22: MacBook + iPhone WG configs use
`DNS = 10.8.0.2, 1.1.1.1`. Private names only resolve when Delta is up
(unavoidable — only AdGuard knows them); public internet keeps working during
an outage via the fallback (after a short resolution delay).

## Rollback

```bash
sudo docker compose -f /home/manuel/services/proxy/compose.yaml down
```
Remove the AdGuard rewrite(s). Nothing public changes; clients unaffected.
