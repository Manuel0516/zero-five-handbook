## Goal (final, agreed 2026-08-14)

- **Beta and Gamma** route their internet traffic through Delta
  (`192.168.1.106`), which NATs it out **Mullvad**. That is the entire
  gateway scope — no other device is routed through Delta.
- **Delta itself** keeps its **own Mullvad client** (`wg-quick@mullvad`,
  enabled at boot) so Delta's own traffic also egresses via Mullvad.
- **MSI, MacBook, iPhone, BlackArch** are **unaffected**: normal mesh
  (personal Zero Five VPN), normal internet via the home router, and each
  laptop may run **its own Mullvad toggle** (e.g. MSI) without breaking
  the mesh.
- **Mesh is always direct.** A policy rule (`sport 51820 lookup main`)
  keeps all WireGuard mesh keepalives out of the Mullvad tunnel, on every
  machine, home or roaming.

## Route plan (5 devices, enforced in Delta's nftables)

| Device | Personal VPN (mesh) | Internet egress |
| --- | --- | --- |
| Delta | wg0 10.8.0.2 | Own Mullvad client (always on) |
| Beta | via Delta (mesh + gateway) | **Delta → Mullvad** |
| Gamma | via Delta (mesh + gateway) | **Delta → Mullvad** |
| MSI | normal (direct mesh peers) | Direct / own Mullvad toggle |
| MacBook | normal (direct mesh peers) | Direct / own Mullvad toggle |

Enforcement on Delta (`/etc/nftables.conf`, nftables):

```text
table ip gateway {
    chain forward {
        type filter hook forward priority filter; policy drop;
        ip saddr 192.168.1.166/32 accept   # Beta
        ip saddr 192.168.1.107/32 accept   # Gamma
        ct state established,related accept
    }
    chain postrouting {
        type nat hook postrouting priority srcnat; policy accept;
        ip saddr 192.168.1.166/32 oifname "eth0" masquerade
        ip saddr 192.168.1.166/32 oifname "mullvad" masquerade
        ip saddr 192.168.1.107/32 oifname "eth0" masquerade
        ip saddr 192.168.1.107/32 oifname "mullvad" masquerade
    }
}
```

Forwarding is **dropped for everyone else** — exactly the pre-change
behavior (Delta forwarded nothing before). Only Beta and Gamma sources
are accepted and masqueraded, out `eth0` (tunnel down) or `mullvad`
(tunnel up).

## Mesh-direct rule (the critical piece)

Delta's `wg-quick@mullvad` installs policy rules that route all
non-mesh traffic into the tunnel table:

```text
32764: from all lookup main suppress_prefixlength 0
32765: not from all fwmark 0xca6c lookup 51820
```

Without a bypass, Delta's **outer WireGuard keepalive packets** to mesh
peers (destined to their endpoint IPs — home public IP or roaming IPs)
fall into the tunnel, and the mesh handshake dies. The fix lives in
`/etc/wireguard/mullvad.conf`:

```ini
PostUp   = ip rule add pref 100 from all sport 51820 lookup main
PostDown = ip rule del pref 100 from all sport 51820 lookup main
```

`sport 51820` is Delta's `wg0` listen port — every packet the mesh sends
out originates from that port. The rule sends those packets to the main
table (direct, via the router) **before** the tunnel rules are reached.
Result: mesh keepalives always egress directly, tunnel up or down.

This also fixes the "MSI with its own Mullvad on" case: MSI's keepalives
to Delta arrive via the home router (`192.168.1.1`), Delta replies
direct, handshake completes — verified 2026-08-14 with the MSI's own
Mullvad toggled off after the fix; the MSI peer shows a fresh handshake.

## Toggle and location switching

Delta tunnel is **always on at boot** (`wg-quick@mullvad` enabled). To
manage it:

```bash
sudo systemctl start wg-quick@mullvad    # tunnel up (default state)
sudo systemctl stop wg-quick@mullvad     # tunnel down -> direct egress
sudo mullvad-switch se-sto               # switch Mullvad location (list, --dry-run, --status)
```

`mullvad-switch` (tracked in `zero-five-infra/scripts/mullvad-switch`,
installed `/usr/local/sbin/mullvad-switch`) rewrites only the `[Peer]`
block of `mullvad.conf` from Mullvad's public relay list and restarts the
tunnel. Same script is reusable on MSI/MacBook for their own clients.

## Gateway failover watchdog (Beta + Gamma)

`gateway-watch` (tracked `zero-five-infra/scripts/gateway-watch`,
installed `/usr/local/sbin/gateway-watch`, systemd unit
`zero-five-infra/systemd/gateway-watch.service`) probes Delta every 10 s:

- Delta reachable ⇒ default route via `192.168.1.106` (VPN or direct per
  the toggle).
- Two missed probes ⇒ default route via `192.168.1.1` — no VPN, normal
  internet, within ~20 s of Delta going off.
- Two successful probes ⇒ back to `192.168.1.106` automatically.

Linux only fails over default routes when an *interface* goes down, not
when a next hop becomes unreachable, so the reachability loop is
required. Accepted trade-off: if Delta dies while the tunnel is up,
laptop traffic falls back to the home IP until Delta returns.

## Rollback

In order: `sudo wg-quick down mullvad` → remove the PostUp/PostDown
rules from `mullvad.conf` → restore `/etc/nftables.conf` from
`.bak-gateway-20260814` → restore laptop gateways to `192.168.1.1` (and
disable/remove `gateway-watch`) → remove `/etc/sysctl.d/99-gateway.conf`.
Each step is reversible independently; no state is stored outside these
files.

## Pitfalls / failure modes

- **Forward scope is strict.** Only `192.168.1.166` and `192.168.1.107`
  are forwarded. If a machine's LAN IP changes (Gamma's did — DHCP),
  update the nftables rule or it silently loses gateway egress.
- **The router fallback covers only Delta being off.** While Delta is up,
  laptop egress goes through Delta; if the tunnel itself drops, Delta's
  fail-open forwarding keeps laptops online on the direct path.
- **Laptop running its own Mullvad + mesh:** works now because Delta's
  replies egress via `sport 51820 lookup main`. The laptop's keepalives
  arrive via the home router, not via a Mullvad exit, when the laptop's
  own Mullvad is off; keep the laptop's Mullvad toggle for its *internet*
  traffic, not for the mesh path.
- **Pools may block VPN IPs.** Some mining pools reject datacenter/VPN
  addresses — switch Mullvad server or pool, not a design fix.
- **`wg-quick up mullvad` also routes Delta's own traffic** through the
  tunnel (intended — Delta has its own client). The mesh is excluded via
  the `sport 51820` rule — confirm `ip rule show` after any config
  change.
- **`mullvad.conf` contains a private key** — `chmod 600`, never commit,
  never paste. Mullvad accounts support multiple WireGuard devices; each
  machine should use its own key.
