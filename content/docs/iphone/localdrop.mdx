[LocalDrop](https://github.com/Manuel0516/localdrop) syncs the clipboard and
transfers files between the desktop machines. Its v1 is **push-only from the
iPhone**: the phone cannot run a LocalDrop daemon (no `config.toml` on iOS),
so the iPhone uses **Shortcuts** to POST clipboard/text and files to a desktop
daemon. **Linux → iPhone is not supported in v1** (the reverse direction).

For the current Razer ⇄ MacBook pair, see
[Razer setup](/docs/laptop-razer/development) and
[MacBook LocalDrop](/docs/macbook/localdrop). The MSI has been retired. This page only covers
sending **from the phone**.

## What the phone can do (v1)

| Direction | Supported? |
| --- | --- |
| iPhone → Linux (Razer) — clipboard & files | ✅ via Shortcuts |
| iPhone → MacBook — clipboard & files | ✅ via Shortcuts |
| Linux/Mac → iPhone | ❌ not supported in v1 |

## Destination: the desktop's WireGuard mesh IP

The phone posts directly to the **Razer Linux desktop** through WireGuard:

```
http://10.40.0.12:8765/clipboard   (clipboard text)
http://10.40.0.12:8765/file        (file bytes)
```

The iPhone's active WireGuard profile must include `10.40.0.12/32` in the
peer's `AllowedIPs`. When targeting the MacBook instead, include
`10.40.0.11/32` and use `http://10.40.0.11:8765`. This direct configuration was
owner-verified on 2026-09-09; no LocalDrop relay on Alpha is required.

> The phone is a one-way HTTP **client** — it never opens a listener, so the
> desktop cannot push audio to it. Only the Shortcuts requests above matter.

## Setup (iPhone)

1. Activate the Zero Five WireGuard profile and add the target desktop's `/32`
   mesh address to its peer's `AllowedIPs`.
2. Confirm the desktop daemon is running and listening on `10.40.0.12:8765`.
   On the iPhone, open `http://10.40.0.12:8765/health` in Safari over WireGuard.
   It should return JSON containing `"status":"ok"`.
3. Record the `shared_token` from the Razer/MacBook `config.toml`
   (`[security] shared_token`) — it must match on the phone and the desktop.
4. In the **Shortcuts** app:
   - **Send clipboard to Linux:** `Get Clipboard` → `Get Contents of URL`
     (URL `http://10.40.0.12:8765/clipboard`, method **POST**, headers
     `X-LocalDrop-Token: <token>` + `Content-Type: application/json`, body:
     `source = "iphone"`, `text = <Clipboard variable>`).
   - **Send file to Linux:** `Get File` → `Get Contents of URL`
     (URL `http://10.40.0.12:8765/file`, method **POST**, headers
     `X-LocalDrop-Token: <token>` + `X-LocalDrop-Filename: <name>` +
     `Content-Type: application/octet-stream`, body = file).
5. Trigger the shortcut from the Share Sheet when sending a file.

## Razer firewall repair — 2026-10-04

The Razer listener was healthy locally, but active UFW had no allow rule for
LocalDrop. Added input rules on `wg0`, destination `10.40.0.12`, TCP port 8765,
restricted to the primary iPhone `.21` and optional iPhone Alpha-relay `.32`
identities. The corresponding MacBook `.11` rule was requested separately;
its administrator authentication remained pending during the phone test. No public or LAN-wide port opening was added.
Secret-free rules are recorded in infra at
`settings/razer/localdrop/firewall.rules`. The optional `.32` profile also needs
a reciprocal Razer route through Alpha; allowing its firewall address alone
is not proof that this fallback works. The owner then confirmed the iPhone Safari health endpoint returns `status ok`
and the iPhone-to-Razer Shortcut works. This establishes the primary phone path;
it does not verify the optional fallback or MacBook pairing.

For rollback, remove only the corresponding UFW rules by their current numbered
entries after inspecting `ufw status numbered`; numbering changes after deletions.
Do not disable the firewall to troubleshoot LocalDrop.

The phone must target the current WireGuard URL above. Historical instructions
using MSI LAN address `192.168.1.110` or Alpha relay `10.40.0.1:8765` do not reach
this Razer listener. Normal copy/paste alone does not run the Shortcut or send
anything to the desktop, and desktop-to-iPhone delivery remains unsupported.

## Security

- Keep port `8765` restricted to the trusted LAN and WireGuard mesh. Do not add
  a router port-forward or public reverse-proxy route.
- The home router currently reports **zero** UPnP port-mappings (verified
  2026-08-23), so nothing is exposed via UPnP today.
- The `shared_token` is a secret: it must be identical on the desktop and the
  phone shortcut, but it is never stored in the handbook or the infra repo.

## Troubleshooting

- `401` — the `X-LocalDrop-Token` header the shortcut sends doesn't match the
  desktop's `shared_token`.
- Timeout/refused — confirm WireGuard is active, the target `/32` is in
  `AllowedIPs`, and the desktop daemon is listening on its mesh address.
- Clipboard sync between the desktops themselves (Razer ⇄ MacBook) is the
  separate pair configured on those machines — see
  [MacBook LocalDrop](/docs/macbook/localdrop).
